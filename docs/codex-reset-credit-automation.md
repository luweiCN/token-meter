# Codex 重置卡到期前自动使用

## 能力与证据

Codex 提供可指定重置卡、支持幂等重试的消费接口。自动使用功能接入官方 app-server 协议，并以用户主动开启为前提。

| 能力 | 依据 | 结论 |
|---|---|---|
| 读取可用数量、卡片 ID、类型、状态和到期时间 | [官方账户额度接口](https://learn.chatgpt.com/docs/app-server#6-rate-limits-chatgpt)；本机 Codex CLI 0.160.0 的只读响应 | 可可靠选择即将过期的卡；详情可能为空或不完整，数量以 `availableCount` 为准 |
| 指定某张卡使用 | [官方重置卡接口](https://learn.chatgpt.com/docs/app-server#8-earned-rate-limit-resets-chatgpt)；本机 CLI 生成的 `ConsumeAccountRateLimitResetCreditParams` schema | `creditId` 可选，但本功能必须传入目标卡的真实 ID，不能让服务端自行选择另一张卡 |
| 防止重试重复消费 | 同一官方接口及本机 schema | 每次逻辑尝试使用一个非空 `idempotencyKey`，不确定结果的重试必须复用它 |
| 用户是否必须先耗尽额度 | 官方接口的 `nothingToReset`；桌面客户端提示“你当前的用量暂时无需重置” | 具体资格规则由服务端决定；没有足够证据把“用量达到 100%”或“用量大于 0”硬编码为资格条件 |
| 桌面客户端采用的消费请求 | 本机 ChatGPT 26.917.51856 的静态前端代码 | 使用 `/wham/rate-limit-reset-credits/consume`，请求含 `credit_id`、`redeem_request_id`；该内部 HTTP 路径仅作为交叉证据，不另建消费通道 |

接口结果含义：

- `reset`：已消费，服务端已重置符合条件的额度窗口。
- `alreadyRedeemed`：相同逻辑尝试之前已成功，按幂等成功处理。
- `nothingToReset`：当前没有符合条件的额度窗口，此次未执行重置。
- `noCredit`：没有可用重置卡。

消费完成后必须重新读取 `account/rateLimits/read`，不能从消费响应推算剩余卡数或新的窗口时间。卡片会恢复其支持的已有额度窗口，不能承诺额外累积额度或保证到期前一定能成功使用。

## 设置入口

在现有“设置 → 供应商额度接入 → Codex”项内增加：

> **重置卡到期前自动使用**　默认关闭
>
> 在到期前 1 小时内尝试使用即将过期的重置卡。需要 TokenMeter 运行且联网，是否可以重置由 Codex 判断。

固定提前 60 分钟，只提供开关。禁用 Codex 供应商、暂停扫描或关闭开关时停止后续调度，并取消正在等待的请求；已发送的消费请求仍可能由服务端完成。设置页显示最近的执行状态。卡片只显示剩余天数、小时或分钟，不显示具体到期日期。

开启开关表示授权以后自动使用；安装升级、打开设置页和加载旧缓存均不代表授权。验证使用模拟服务，不消耗真实卡片。

## 执行规则

1. 调度只由 Swift 菜单栏进程负责。基于精确时间戳选出 `0 < expiresAt - now <= 3600` 的卡，不用取整后的界面文案判断。
2. 开启后每分钟检查，并在应用启动、电脑唤醒和设置变化时重新评估。执行前实时读取登录账户、额度和卡片详情，只接受有效 ID、可用状态、支持类型和未过期的目标卡；旧缓存只用于显示。
3. 优先处理到期最早的卡，每次只处理一张。成功后先刷新服务端状态；禁止对卡片列表并发批量消费。
4. 向服务端发送前，持久化账户及卡片指纹、幂等键和尝试状态。相同账户与卡片的未完成尝试只能有一个所有者，应用重启后仍能复用原幂等键。
5. 超时、断线或异常响应表示结果不确定，保留原尝试，后续只以相同卡片 ID 和相同幂等键核对或重试。禁止换一个键盲目重发。
6. 收到 `reset` 或 `alreadyRedeemed` 就结束该次尝试；后续额度读取失败不能触发再次消费。
7. 收到 `nothingToReset` 后停止当前尝试并展示原因；仅在后续新鲜额度状态发生变化且卡仍处于有效时间内时重新评估，避免持续空转。`noCredit` 则刷新列表，不自动改用另一张未到期的卡。
8. 睡眠、关机、退出应用或断网时无法保证准点执行。恢复后若卡仍有效且处于触发窗口，可以重新评估；已到期的卡直接跳过，不伪报成功。

## 与现有实现的衔接

- 设置沿用现有 SQLite `settings`、`SettingsStore`、Electron `SettingsRepository` 和 `settingsChanged` 通道，缺失值解析为关闭，不增加第二份配置文件。
- Codex 数据沿用 `CodexUsageProvider` 的 app-server 通道。让一次 `account/rateLimits/read` 同时提供额度和重置卡，替代额外 HTTP 取卡请求；消费与后续确认使用同一套协议客户端。
- 原始卡片 ID 仅用于当前实时响应和请求；缓存及持久化尝试使用不可逆指纹，不把完整 ID、凭证或账户隐私写入日志。缺少可靠卡片详情时保留显示能力，但不执行自动使用。
- 调度和消费逻辑独立于 `ResetCreditDisplay`；显示层继续只负责时间格式化。单一调度所有者负责并发、停止和恢复。
- `codex_reset_redemptions` 通过现有数据库迁移入口创建，作为不可重建的持久记录保留，不随统计表重建删除。使用独立 SQLite 连接与原子领取，避免和扫描事务交错。

## 验收

- 默认关闭；禁用供应商、关闭设置、缓存过旧、缺少 ID 或执行前后账户不一致时均不能消费。
- 覆盖 3601、3600、1、0 秒边界，以及启动、唤醒、时钟变化和已过期场景。
- 指定即将到期的卡，不能消耗其他卡；多卡场景串行执行。
- 超时但服务端已经成功时，重试仍只消费一次；重启和重复调度不产生新幂等键。
- 成功后刷新失败不会再次消费；`nothingToReset`、`noCredit` 与结果不确定有不同状态。
- 所有消费测试使用模拟响应。未经单独授权不以用户的真实卡片做端到端消费验证。

协议客户端在消费前通过本机 CLI 的生成 schema 确认支持 `creditId`，不支持选择卡片的旧客户端停止自动使用，避免未知字段被忽略后误用其他卡。
